# 调研任务：发行状态页如何保证「单一现役结论」与已打 tag / 商店上架状态一致

## 背景（已发生事实，不要重复推导）

- 单仓浏览器扩展（Chrome MV3 + Firefox），零运行时依赖，文档为纯 Markdown，无站点生成器。
- 存在一个人工维护的发行状态页，内容包含：目标版本、三道发行门（CI 全绿 / 人工黄金路径用户声明 / 静态站点可达）、在效豁免台账、在办欠账。
- 已发生故障：同一页内三套状态并存——页首标题宣称「三门达成」，紧邻的表格却写「不可发行」，第三节又给出实测三门达成；发行终谳块留空待填；历史 CI 运行未标注已被取代。读者只读本页无法得到唯一结论。
- 约束（不得违反）：可发行性由三条件合取定义，缺一不可；人工门只能由用户本人声明，自动化与文档不得代签；已推送的提交历史不得改写。

## 需要你回答（每问给「推荐 + 理由 + 可核验来源」）

1. 工业界如何让「人工维护的发行状态页 / 状态看板」与其所描述的事实源（git tag、商店上架状态、CI 运行）保持一致、防止漂移？请给出并对比至少三种真实做法及其失败模式，并给出推荐组合。

2. 当同一文档内出现多套互相矛盾的状态表述时，成熟的收敛模式是什么（例如单一权威块 + 其余降级为指针、状态机式单一现役态、旧态显式标记为已取代而非删除）？请说明各自的审计链影响与误读风险。

3. 对历史证据（已被新证据取代的旧 CI 运行 / 旧结论）应如何处理，才能既不丢失审计链又不误导读者？
