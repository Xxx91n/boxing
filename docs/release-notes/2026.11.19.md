Boxing 2026.11.19

这一版把两件拖了很久的事做完了：三处标题改成真正的输入框；自动备份搬进浏览器后台，不开着新标签页也会按时跑。

## 这版你能感觉到的变化

### 标题编辑
- 大盒子、小盒子、盒内顶部的标题都是原生单行输入框。第一次点击全选，第二次点击光标落在你点的位置；Enter 提交、Esc 取消、点别处保存；中文输入法选字时按 Enter 不会误提交。
- 粘贴只留纯文本，换行变成空格；空标题回退到该类型的默认名字。

### 自动备份
- **默认关闭，开了才动**。打开后立刻试一次，之后按你选的周期（最短 1 小时）在后台执行；浏览器关掉不跑，重开后只补一次。
- **后台独占**：不用开着 Boxing 页面，也不会出现页面和后台同时上传。
- **不覆盖不认识的远端**：第一次只在远端确实为空时创建；已有文件必须对得上本机上次写过的版本才更新。别人改过、服务器不认条件写、结果拿不准，都会停下并说明原因，不会闷头覆盖。
- **失败有限重试**：断网、超时这类临时故障最多再试 3 次（约 5/15/60 分钟，且不会早于服务器给的 Retry-After）；鉴权失败、权限不足、目标变了、远端冲突一次都不重试。
- **本地和云端各记各的**：本地快照失败不会冒充云端成功；关掉开关会立刻停掉正在进行的上传；确认成功、明确没发出去、结果待确认三种情况都按实际记录。
- **权限没有变大**：Chrome 发行包只在你自己启用 WebDAV/Gist 时才申请主机权限；Firefox 沿用它的主机权限模型。没有新增系统通知权限，失败提示只在工具栏角标和设置页出现。

### 验证
- 新增一个跑真构建的发布门槛用例：真的加载 `dist/boxing-chrome`、真的跑后台 service worker，验证全新安装零上传、开开关立刻备份、关掉所有页面照样备份、关开关立刻停。
- Firefox 侧的后台 alarm、权限、云端故障、重试和重启补做，仍按仓库里的发行清单人工核对。

## English

Boxing 2026.11.19

This release finishes two long-standing pieces: the three titles are real text inputs, and auto-backup now runs in the browser background, without a new-tab page left open.

## What you will notice

### Title editing
- The large-box title, small-box title and inner-page title are native single-line inputs. The first click selects the whole name, the second click places the caret exactly where you clicked. Enter commits, Esc cancels, clicking away saves; pressing Enter while an IME is composing does not submit.
- Pasting keeps plain text only (line breaks become spaces), and an empty title falls back to that box type's default name.

### Auto-backup
- **Off by default; it only runs after you opt in.** Turning it on tries once immediately, then follows the interval you picked (one hour minimum). It does not run while the browser is closed, and a restart catches up at most once.
- **Background only**: no Boxing page needs to be open, and the page and the worker cannot upload at the same time.
- **It never overwrites a remote it does not recognise**: the first write only happens when the remote is verifiably empty; an existing file is updated only when it matches the version this browser wrote last. An external change, a server that ignores conditional writes, or an uncertain result all stop the run with a plain-language reason instead of overwriting.
- **Bounded retries**: a dropped connection or timeout gets at most three extra attempts (about 5, 15 and 60 minutes later, never earlier than the server's `Retry-After`). Rejected credentials, missing permission, a changed target and remote conflicts never retry on their own.
- **Local and remote results stay separate**: a failed local snapshot never counts as a cloud success. Turning the switch off stops an upload in flight; confirmed success, a definite miss and an uncertain result are each recorded as what they really are.
- **No extra permissions**: the Chrome package requests host access only when you enable WebDAV or Gist; Firefox keeps its own host-permission model. No system notifications are added; failures only show on the toolbar badge and in settings.

### Verification
- A new release-gate lane loads the real `dist/boxing-chrome` build with a real background service worker and checks four things: a fresh install uploads nothing, flipping the switch on backs up immediately, backup still runs with every extension page closed, and turning the switch off stops it at once.
- On Firefox, background alarms, permissions, cloud failures, retries and restart catch-up are still checked by hand with the checklist in the repository.
